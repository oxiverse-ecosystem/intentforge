INTENTFORGE /search API — HONEST UX AUDIT (live, localhost:4000)
================================================================
Date: 2026-07-19  |  Method: 69 real queries against the live API
Battery: _searchtest/ux_probe.py (51) + _searchtest/ux_probe2.py (18)
Raw results: _searchtest/ux_probe_results.json, _searchtest/ux_probe2_results.json

Bottom line: The score-calibration and gibberish/edge-case fixes from the
prior audit (SEARCH_AUDIT_PLAN.md) are DONE and verified. But the
NEGATIVE-CONSTRAINT path does not actually exclude anything — it only softly
penalizes, so "not X" queries still return results dominated by X. And
technical/doc queries are systematically misclassified as navigational.
Those two are real, root-caused code bugs.


WHAT WORKS (verified against live responses)
--------------------------------------------
1. Score calibration is fixed. Of 44 multi-result queries, 0 had flat/equal
   scores and 0 were >50% saturated. Ranking is now differentiable.
   (Prior audit Phase 0 — confirmed resolved.)

2. Gibberish + edge handling is clean:
   - "asdfghjkl qwerty zxcvbnm" -> 400, query_quality="junk", message present
   - "wergwreg weubf iweb"       -> 200, query_quality="low" (warns UI)
   - q="", "a", "the", "12345"   -> 400 with structured error JSON
   (Prior audit Phase 7/8 — confirmed resolved.)

3. Freshness intent is real and date-honest:
   - "latest ai news 2026" -> intent=fresh, 100% of datable results are 2026
   - "recent rust releases" -> fresh, returns docs.rs/github releases
   - "breaking news today" -> fresh, returns live news orgs (AP, Indian Express)
   (Prior audit Phase 4 — confirmed resolved.)

4. Comparison intent is strong: "rust vs go" conf=0.90, triple-comparison 0.90.

5. Operator parsing is solid: site:, filetype:, after:, intitle:, inurl:,
   price:<N / price:>N, "under N"/"less than N" NL forms all parsed into
   structured_constraints correctly.

6. "alternative to X" / "instead of X" correctly become NEGATIVE (not
   reference) — "search engine alternative to google" does not return Google
   as the top hit. (Prior audit BUG #3 — confirmed resolved.)

7. Upstream failure is graceful: empty operator queries return
   error="upstream_unavailable" + a HONEST "temporary, retry" message, never 5xx.


CONFIRMED FAILURES (real query -> real numbers)
-----------------------------------------------

P0 — NEGATIVE CONSTRAINTS DON'T EXCLUDE; THEY ONLY SOFTLY PENALIZE
Root cause: services/gateway/src/main.rs
  - should_filter_by_constraints (line 2152-2155): hard-drop only when
    c_score < threshold, where threshold = 0.05 for a single negation.
  - constraint_score (line 1486-1508): the penalty is a MULTIPLIER
    (x0.5 content, x0.02-0.20 title), not a drop. A page whose TITLE/subject
    IS the excluded term still clears c_score=0.05 and survives.
  - Line 2140: "is_only_negative" returns false (never an issue here).
  - Line 1511: comparison/alt-listing pages get a single FLAT penalty, so a
    "Best X" list that mentions the excluded option barely drops.

Evidence (pct of results that still contain the excluded term):
  - "best python ide not pycharm"          47% (8/17) still say PyCharm
  - "static site generator instead of jekyll" 62% (5/8) still say Jekyll
  - "best laptop for video editing not macbook" 33% (6/18) still say MacBook
  - "browser not chrome not edge not firefox" chrome 20%, firefox 13%, edge 7%
  - "text editor without vim"              16%   | "linux distro no ubuntu" 33%
  - "programming language other than java" 33%   | "search engine alt to google" 11%
  - "python web framework not django"      19%
  Across the 51-query battery, 8 queries leaked the excluded term into results.
  Worst case: a comparison page (#1 slot for jekyll) is uncfiltered because
  it's treated as an "alt-listing page".

  UX impact: a user who says "not X" sees X in the top 5. This is the single
  most damaging constraint bug. Fix is to hard-exclude when the excluded term
  appears in the TITLE (or is the dominant topic) for a NON-alt page, while
  keeping the soft-penalty only for incidental mentions inside comparison pages.


P1 — TECHNICAL / DOC QUERIES MISCLASSIFIED AS NAVIGATIONAL
Root cause: intent classifier over-predicts "navigational". Confidences are
LOW (0.37) but still flip the category, and navigational applies a 90-DAY
freshness half-life (API_REFERENCE.md) — so technical docs can surface stale.

Evidence (0 of 6 technical queries classified "technical"):
  - "kubernetes ingress tls configuration"  -> navigational 0.37
  - "python asyncio event loop explained"    -> navigational
  - "configure nginx reverse proxy with ssl"  -> how-to (wanted technical)
  - bare brands: kubernetes, docker, nginx, postgresql, terraform, redis
    -> mostly navigational
  Distribution for kubernetes: navigational 0.36 / how-to 0.24 — thin margin,
  so a low-confidence flip is happening.

  UX impact: technical results get the wrong freshness curve + wrong ranking
  boosts; a "kubernetes tls" searcher may get a 2-year-old doc ranked high.


P1 — COMPOUND site:+filetype: QUERIES RETURN 0 WHEN SITE-ALONE WORKS
Evidence:
  - "python tutorial site:docs.python.org filetype:pdf" -> n=0 (upstream timeout)
  - "python tutorial site:realpython.com"              -> n=2 (works)
  - "python tutorial site:realpython.com filetype:pdf"  -> n=0
  The site:+filetype: combo is forwarded to upstream, which often returns
  nothing; the local filetype fall-open (main.rs 1956-1964) protects
  extensionless URLs but can't rescue a fully-empty upstream response.
  Not strictly a gateway bug (it's upstream), but the UX is poor: a valid
  operator query yields an empty page even though site-only works.
  Suggestion: when site-scoped upstream returns 0 AND filetype is set, retry
  with filetype relaxed, or at minimum propagate the honest upstream message
  (already partly done).


P2 — MINOR
  - "best pizza near me open now" -> local intent but no visible open-now
    time filtering in response (local is geo-dependent; low signal here).
  - "wergwreg weubf iweb" (low-quality) -> 90% non-Latin results; the
    low-quality path flags quality="low" but doesn't hard-drop, so foreign
    results leak. Acceptable but could be tightened.


RECOMMENDATIONS (priority order)
--------------------------------
1. [P0] Negative constraints = hard-exclude for title/dominant-topic matches
   on non-alt pages; keep soft-penalty only for incidental mentions inside
   comparison/alt-listing pages. Code: services/gateway/src/main.rs
   should_filter_by_constraints (line 2144-2155) + constraint_score penalty.
2. [P1] Fix navigational over-prediction: add a confidence floor + brand/token
   gate so bare technical terms and multi-token doc phrases don't flip to
   navigational unless brand AND conf>=~0.8. Code: services/intent-engine.
3. [P1] Compound site:+filetype: fall-back / honest-empty handling.
